# Chefs Help Chefs MVP：UI / UX 设计规范

**状态：** 已确认  
**日期：** 2026-09-10  
**范围：** 城市引入页 + 上海机场标准关卡 1–50 的 MVP  
**产品逻辑唯一依据：** [2026-09-09-airplane-chefs-mvp-design.md](superpowers/specs/2026-09-09-airplane-chefs-mvp-design.md)

## 1. 文档目标与边界

本规范把已确认的产品需求转译为可执行的页面结构、交互规则、状态与响应式行为。它不改变产品逻辑，不新增产品功能，也不定义实施方案。

本轮确认的重点是 UX、页面结构与组件行为。城市引入页已确认采用“全幅城市场景轮播 + 悬浮信息层”的视觉结构；除此页面外，色板数值、字体、图标与动效仍暂缓决定。实施视觉时仍必须遵守产品要求：使用克制的航空主题与蓝色系业务界面，且装饰不得干扰表单、预算、成本和结果数值的阅读。

## 2. 设计原则

- 玩家端先提供清晰的城市进入体验，再服务手机上的一次独立计算：少步骤、少跳转、可连续填写。
- 管理端优先服务桌面数据维护：稳定导航、清晰表格、可快速定位错误。
- 所有关键数值都带文字标签；状态、预算与错误不能只依赖颜色或图标。
- 不增加攻略、方案比较、历史、账户、仪表盘或其他 MVP 范围外能力。
- 对大量数值录入，优先让字段与其所属对象相邻，并在出错处直接说明如何修正。

## 3. 整体信息架构

### 3.1 玩家端

```text
城市引入页（默认入口）
├─ 滑动浏览固定的 18 座城市路线
├─ 上海：已开放 → 点击进入
└─ 其他城市：暂未开放 → 不可进入

上海玩家计算页
├─ 清除草稿确认弹窗
└─ 计算最佳方案
   └─ 独立结果页
      ├─ 成功：预计可达三星
      ├─ 已达三星：无需升级
      └─ 无解：暂未找到可行升级方案
```

玩家端没有账号、历史、收藏或方案列表。城市引入页是默认入口；上海是唯一可进入的城市。结果页仅展示本次输入计算得到的唯一结论。用户从结果页返回时，原输入及本机草稿均保留。

### 3.2 管理端

```text
管理员登录页
└─ 验证通过后：上海标准关卡（默认模块）
   ├─ 食物分类
   ├─ 食物升级目录
   └─ 纪念品

跨模块交互
├─ 单条新增 / 编辑：右侧编辑面板
├─ 删除：二次确认弹窗（纪念品除外）
└─ 关卡 / 食物目录导入：独立导入结果页
```

管理端不设置仪表盘。登录成功后直接进入“上海标准关卡”列表。四个既定数据模块由固定左侧导航切换；导入结果页不是常规导航项，而是当前模块导入流程的一部分。

## 4. 玩家端页面清单

| 页面 / 覆层 | 目的 | 进入方式 | 离开方式 |
| --- | --- | --- | --- |
| 城市引入页 | 浏览固定城市路线并进入唯一开放的上海 | 玩家端默认入口；浏览器返回 | 点击上海的“点击进入”进入上海计算页 |
| 上海玩家计算页 | 收集本次计算的全部输入 | 城市引入页点击上海的“点击进入”；从结果页返回 | 计算成功、已达三星或无解后进入结果页 |

| 清除草稿确认弹窗 | 防止误清除本机输入 | 计算页点击“清除草稿” | 取消关闭；确认后清除并回到默认表单 |

## 5. 城市引入页

### 5.1 页面目的

作为玩家端默认入口，展示完整的固定城市路线，让玩家浏览城市并从唯一已开放的上海进入计算流程。它是未来城市扩展的前端入口，但不为未开放城市提供关卡、数据或计算能力。

### 5.2 固定城市路线

城市按下列固定顺序组成一个连续选择器：

> 丹佛 → 悉尼 → 伦敦 → 纽约 → 新加坡 → 东京 → 那不勒斯 → 里约热内卢 → 开普敦 → 巴黎 → 雅加达 → 洛杉矶 → 墨西哥 → 孟买 → 札幌 → 柏林 → 上海 → 布宜诺斯艾利斯

路线不是后台维护数据，也不为其余 17 座城市新增任何管理配置。

### 5.3 信息层级、结构与视觉规则

1. **品牌层：** `Chefs Help Chefs` 与 slogan `Smarter plans. More stars.`；可使用克制的航空航线提示。
2. **城市轮播主舞台：** 从品牌层下方延伸到页面主体的无边界、全幅城市场景。
3. **选中城市信息层：** 在场景底部使用对比充分的渐变遮罩，叠加城市名与开放状态。
4. **行动层：** 仅上海显示主按钮“点击进入”。
5. **滑动提示层：** 精简分页点与“左右滑动，浏览完整城市路线”提示。

城市选择器不得使用独立卡片、圆角卡片容器、描边、阴影、卡片间距或网格列表。每座城市是一张连续的全幅轮播场景；城市切换时，当前场景从左右滑入，形成无边界的航线体验。城市视觉素材是前端静态资源，不由管理端维护，也不表示该城市已支持计算。

已确认页面不显示“选择城市”标题，也不显示“探索全球航线，找到你的下一站”辅助文案。

### 5.4 交互、状态与文案

- **首次加载：** 上海置于轮播视口中心并默认选中；轮播可在上海两侧露出相邻场景的连续边缘，提示可横向浏览。
- **上海已开放：** 信息层显示“上海”“已开放”，并显示唯一可操作主按钮“点击进入”。点击后进入上海玩家计算页。
- **未开放城市：** 用户可以手势滑动、点击或用键盘选择任一城市。选中后居中显示其场景和“暂未开放”；不显示进入按钮，不创建草稿，不加载关卡或计算数据。
- **浏览：** 手机使用原生横向滑动；桌面可使用拖动、滚轮横向移动或键盘焦点逐项移动。轮播本身是玩家端唯一允许横向滑动的区域。
- **返回：** 计算页不新增城市管理或切换城市功能；浏览器返回可回到城市引入页，并保留当前城市选择状态。
- **加载与失败：** 静态路线可立即呈现；城市视觉资源未准备好时显示与轮播尺寸一致的中性骨架场景，不把城市误标为未开放。资源加载失败时保留城市名称和开放状态文字，并提供重试。

### 5.5 响应式

- **手机：** 城市场景占据主要可视区域；上海默认居中；只以相邻场景的边缘和分页点提示连续滑动。
- **宽屏：** 主场景保持居中，增加可见的相邻场景宽度；不把轮播退化为城市卡片列表。
- **可读性：** 城市名、开放状态、主按钮与滑动提示必须位于对比充分的遮罩层上，不依赖照片本身的明暗。

## 6. 上海玩家计算页

### 6.1 页面目的

让匿名玩家在单一表单页完成关卡、当前收入、预算、升级候选与纪念品录入，并在不离开输入上下文的情况下修正错误。

### 6.2 信息层级与模块顺序

1. 页面标题与固定机场“上海”。
2. 当前状态：关卡、三星目标、当前总收入。
3. 资源预算与成本偏好。
4. 食物升级候选。
5. 纪念品。
6. 草稿说明、清除草稿与“计算最佳方案”。

此顺序与用户提供信息的因果顺序一致：先知道缺口，再限定资源，再录入可选手段。

### 6.3 结构、组件与交互

#### 当前状态与预算区块

- **关卡选择：** 关卡编号 1–50 的单选下拉控件。选定后显示不可编辑的三星目标收入。
- **当前总收入：** 数字输入框，附说明“未使用纪念品、在当前配置下完成该关全部订单的总收入”。
- **金币预算、钻石预算：** 两个独立数字输入框，均附“留空表示不限”说明。
- **成本偏好：** 必选单选组：“优先省金币”与“优先省钻石”。

此区块默认展开。玩家可以看到目标收入与当前收入的关系，但页面不在填写过程中预先给出未定义的方案建议。

#### 食物升级候选区块

- 后台目录中的最多 10 个项目以固定目录顺序展示。
- 每项展示名称、分类标签和“纳入计算”复选框。
- 勾选某项后，在同一项目下展开三项数字输入：收入增量、金币成本、钻石成本。
- 未勾选项不展开、不校验、不参与计算。
- 已勾选项目按目录位置保留，不能在玩家端新增、删除、排序或重复选择。

这是“目录清单 + 勾选后行内展开”模式。名称、分类和三个数字字段始终相邻，便于连续录入和错误定位。

#### 纪念品区块

- 固定展示两种后台配置的纪念品。
- 每种纪念品包含“允许使用”复选框和库存数字输入。
- 未允许时，库存不显示为必填也不参与校验。
- 允许后显示库存输入与说明“库存为 0 时仍可购买；留空不等于 0”。
- 玩家不填写纪念品使用数量；系统在结果中给出该数量及购买信息。

#### 草稿与提交

- 页面显示静态说明：“本次输入会自动保存到此浏览器”。
- “清除草稿”为次级文字操作；点击后必须先经确认弹窗。
- 表单末尾放置主按钮“计算最佳方案”。不增加多步骤向导、预览页或备选方案入口。

### 6.4 表单展开、校验与错误规则

- “当前状态与预算”默认展开；“食物升级”和“纪念品”可折叠。
- 用户打开的区块保持展开，便于连续输入与复查。
- 用户离开字段时执行该字段校验；点击“计算最佳方案”时执行全量校验。
- 若全量校验发现折叠区块内的错误，系统自动展开该区块并滚动至第一个错误字段。
- 错误显示在字段正下方，使用明确文字、错误边框和图标；文字是必需的信息载体。
- 合法提交时，按钮进入“计算中”加载状态并禁用重复点击。

| 条件 | 字段提示文案原则 | 提交行为 |
| --- | --- | --- |
| 当前总收入为空、为小数或负数 | 说明需输入“允许为 0 的非负整数” | 阻止计算 |
| 预算填写非法 | 说明需输入“允许为 0 的非负整数”，并提示留空表示不限 | 阻止计算 |
| 未选成本偏好 | “请选择成本偏好” | 阻止计算 |
| 已选食物的收入增量为空、非整数或不大于 0 | “收入增量必须为正整数” | 阻止计算 |
| 已选食物的金币 / 钻石成本非法 | “成本必须为允许 0 的非负整数” | 阻止计算 |
| 已允许纪念品但库存为空或非法 | “允许使用纪念品时必须填写允许为 0 的非负整数库存” | 阻止计算 |
| 当前收入低于目标且没有任何食物或允许纪念品 | “请至少选择一项食物升级或允许一种纪念品” | 阻止计算 |

### 6.5 页面状态与异常

- **初始 / 恢复草稿：** 显示默认值或已恢复的本机输入；不把未填写表单误称为空状态。
- **已自动保存：** 以低干扰的静态说明表达，不增加历史或云同步入口。
- **输入不足：** 停留在当前页，定位字段或候选项错误。
- **计算中：** CTA 显示加载状态，表单保持现有值。
- **计算服务失败：** 保留所有输入，显示可重试的错误提示；不清除草稿。
- **清除草稿：** 确认后清空输入，并保证下一次加载不恢复已清除的草稿。

### 6.6 响应式

- **手机优先：** 单列布局、全宽控件、无横向滚动。
- **窄屏数值输入：** 食物项目的三个数字字段从同一行改为纵向排列，仍保持与对应食物相邻。
- **桌面：** 维持可读的单列表单最大宽度，不将长表单拉成过宽表格，也不添加干扰填写的侧栏。

## 7. 玩家结果页

### 7.1 页面目的

让用户立即确认是否可达三星，并按唯一推荐方案实际操作，同时能复核收入、预算和成本偏好。

### 7.2 成功结果的信息层级

结果页严格采用“结论 → 操作 → 成本”的顺序：

1. **状态结论卡：** “预计可达三星”。
2. **收入指标：** 当前收入、三星目标、达星余量。
3. **照此操作：** 推荐食物升级与推荐纪念品的完整清单。
4. **总成本：** 金币总成本、钻石总成本及相对已填写预算的余量。
5. **方案说明：** 选择的成本偏好、预计新增收入、方案后总收入。
6. **返回修改：** 次级按钮“返回并修改输入”。

### 7.3 成功结果模块与组件

| 模块 | 必须展示的信息 |
| --- | --- |
| 状态结论卡 | “预计可达三星”及方案后总收入 |
| 收入指标组 | 所选关卡、三星目标、当前收入、收入缺口、预计新增收入、方案后总收入、超过目标的余量 |
| 食物操作项 | 名称、分类、收入增量、金币成本、钻石成本 |
| 纪念品操作项 | 使用数量、原库存消耗、购买包数、购买数量、购买后剩余数量、钻石成本 |
| 成本卡 | 金币总成本、钻石总成本、各自预算剩余；预算未填写时明确标注“不限预算” |
| 方案说明 | 玩家选择的成本偏好 |

不提供备选方案、所有方案、排序切换、比较、收藏或分享功能。

### 7.4 非成功结果

- **已达三星：** 显示“当前配置已满足三星，无需升级”，并显示关卡、当前收入、三星目标及“返回并修改输入”。不显示升级清单。
- **无解：** 显示“暂未找到可行升级方案”，并显示收入缺口和有限最大可增加收入；说明在当前候选项与预算下不可达成。不得把“无上限”作为无解结果展示。
- **输入非法或输入不足：** 不进入结果页，留在计算页完成校验与修正。

### 7.5 响应式

- **手机：** 单列纵向阅读，不使用标签页或折叠明细，避免用户遗漏操作步骤。
- **桌面：** 顶部结论与收入指标可并列；操作清单和成本卡可在更宽区域并列，但页面的阅读顺序不改变。

## 8. 管理端页面清单

| 页面 / 覆层 | 目的 | 主要操作 |
| --- | --- | --- |
| 管理员登录页 | 验证共享管理员口令 | 输入并提交口令 |
| 上海标准关卡列表 | 维护关卡编号与三星目标收入 | 搜索、新增、编辑、删除、导入、导出 |
| 食物分类列表 | 维护食物分类 | 搜索、新增、编辑、删除 |

## 9. 管理端共用框架

### 9.1 页面目的与信息层级

管理端以桌面数据维护效率为先，采用以下稳定结构：

1. 顶部产品与“管理后台”标识。
2. 固定左侧导航：上海标准关卡、食物分类、食物升级目录、纪念品。
3. 主内容区：模块标题、搜索、模块操作、数据列表。
4. 右侧编辑面板：新增或编辑单条数据。

登录后默认进入“上海标准关卡”。不设置仪表盘、运营数据或最近使用模块。

### 9.2 共用交互与状态

- 列表均有搜索；搜索词保留直到用户清除、切换模块或主动重置。
- 单条新增和编辑均在右侧编辑面板完成。保存成功后关闭面板、刷新原列表位置，并给出文字成功反馈。
- 删除始终使用独立二次确认弹窗，明确显示被删除对象及不可逆提示。
- 列表加载时显示骨架行，避免使用会被误解为“没有数据”的空白区域。
- 初始空状态显示说明与适用的“新增”或“导入”入口；搜索无结果显示“没有匹配的数据”，并保留搜索词。
- 保存、删除、导入等请求失败时，保留编辑面板或当前页面的已有输入，并提供重试入口。

### 9.3 响应式

- **桌面：** 固定左侧导航、完整数据表、右侧编辑面板。
- **中等宽度：** 侧栏收窄为图标或可展开导航；表格仍保持可读列宽。
- **窄屏：** 导航收纳至菜单；一般数据列表转为带字段标签的卡片；右侧编辑面板改为全屏面板。
- **导入错误表：** 窄屏保留受控横向滚动容器，确保行号、字段和错误原因完整可读。

## 10. 管理端各页面规范

### 10.1 管理员登录页

**目的：** 通过部署时配置的共享管理员口令控制后台访问。

**组件：** 产品标识、“管理后台”标题、口令输入框、登录按钮、字段错误提示。

**交互与状态：**

- 页面加载后口令输入框自动获得焦点；支持回车提交。
- 提交中，登录按钮显示加载状态并禁止重复提交。
- 口令错误时，在字段附近显示“口令不正确，请重试”；不暴露额外认证信息。
- 验证成功后进入上海标准关卡列表。
- 移动端与桌面端均使用居中、窄宽单列表单。

### 10.2 上海标准关卡列表

**目的：** 维护上海标准关卡 1–50 的三星目标收入。

**信息层级与组件：**

- 标题“上海标准关卡”。
- 按关卡编号搜索的搜索框。
- “新增关卡”“导入 CSV/XLSX”“导出 CSV/XLSX”操作。
- 数据列：关卡编号、三星目标收入、操作。
- 行操作：编辑、删除。

**编辑面板：** 关卡编号、三星目标收入。编号必须是 1–50 的整数；目标收入必须是正整数。错误紧贴字段显示。

**异常：** 重复唯一键、非法编号和非法目标收入必须阻止保存并给出具体提示。

### 10.3 食物分类列表

**目的：** 维护供食物升级目录引用的分类。

**信息层级与组件：** 标题、按名称搜索、新增分类、分类名称列表、编辑与删除操作。

**编辑面板：** 仅含必填分类名称。

**异常：** 若分类被任一食物升级项引用，删除确认不能继续，改为明确提示“该分类仍被食物升级项引用，请先迁移或删除关联升级项”。界面不提供自动迁移功能。

### 10.4 食物升级目录列表

**目的：** 维护玩家端可勾选的食物升级候选，目录最多 10 项。

**信息层级与组件：**

- 标题“食物升级目录”。
- 按名称搜索。
- “新增食物升级项”“导入 CSV/XLSX”“导出 CSV/XLSX”。
- 数据列：名称、分类、操作。

**编辑面板：** 名称与分类下拉选择；下拉仅显示已有分类。

**状态与异常：**

- 达到 10 项时，新增入口不可用并说明“目录最多 10 项”。
- 名称重复、分类不存在或导入后超过 10 项时，阻止写入并给出具体原因。
- 导入第 11 项必须进入导入失败结果，不产生部分写入。

### 10.5 纪念品配置列表

**目的：** 编辑固定两种纪念品的配置。

**信息层级与组件：** 标题、按名称搜索、两条固定配置记录。列表列为名称、单个收入增量、每包数量（固定显示 5）、每包钻石价格、编辑操作。

**编辑面板：** 名称、单个收入增量、每包数量（只读值 5）、每包钻石价格。

**规则与异常：** 单个收入增量为正整数；包价为允许 0 的非负整数。此模块不提供新增、删除、CSV/XLSX 导入或导出，以保持“两种固定纪念品”范围。

### 10.6 导入流程与导入结果页

**目的：** 安全处理关卡或食物升级目录的 CSV/XLSX 文件。

**流程：**

1. 用户在对应列表点击“导入”。
2. 选择 CSV 或 XLSX 文件。
3. 系统显示“正在校验文件”。
4. 有任一错误时，进入独立导入结果页，整份文件不写入。
5. 文件合法时，直接执行原子导入，并返回原列表显示成功反馈。

**导入结果页结构：**

- 数据集名称、文件名、结果结论。
- 失败时醒目标明“未导入，未产生任何数据变更”。
- 全宽错误表：行号、字段、错误原因，列出全部错误。
- 操作：“重新选择文件”“返回列表”。

**成功状态：** 显示导入成功文字反馈后返回原列表。导入不增加额外确认步骤、导入历史、模板下载或批量回滚功能。

## 11. 跨页面状态规范

| 状态 | 玩家端表现 | 管理端表现 |
| --- | --- | --- |
| 城市引入初始 | 上海在全幅轮播中央默认选中，并显示“已开放”与“点击进入” | 不适用 |
| 城市暂未开放 | 显示所选城市与“暂未开放”；不显示进入按钮，也不加载计算数据 | 不适用 |
| 城市视觉加载失败 | 保留城市名称与开放状态，展示中性骨架场景与重试入口 | 不适用 |
| 加载 | 计算按钮显示“计算中”并禁止重复提交 | 列表骨架行；登录、保存与导入显示进行中状态 |
| 空状态 | 不将未填写计算表单称为空状态 | 首次无数据说明和新增 / 导入入口 |
| 搜索无结果 | 不适用 | 保留搜索词并显示“没有匹配的数据” |
| 成功 | 结果页“预计可达三星” | 保存、删除、合法导入后的文字成功反馈 |
| 已达三星 | 独立结果页明确写“当前配置已满足三星，无需升级” | 不适用 |
| 无解 | 独立结果页显示收入缺口和有限最大可增加收入 | 不适用 |
| 输入错误 | 字段旁文字提示；提交时定位首个错误 | 表单字段旁提示；导入通过错误表显示全部行级问题 |
| 服务失败 | 保留输入并提供重试 | 保留表单或当前页状态并提供重试 |
| 破坏性操作 | 清除草稿需二次确认 | 删除需二次确认；导入失败明确未写入数据 |

## 13. UI 验收标准

### 13.1 玩家端

- [ ] 玩家端默认先进入城市引入页；上海首次加载时在无边界城市轮播中央默认选中。
- [ ] 18 座城市按 PRD 固定顺序可完整浏览；轮播不使用卡片、网格、描边、圆角卡片容器或城市卡片间距。
- [ ] 上海显示“上海”“已开放”和唯一主按钮“点击进入”；点击后才进入上海玩家计算页。
- [ ] 其余 17 座城市可被选择并显示“暂未开放”，但不显示进入按钮，不产生草稿，也不加载计算数据。
- [ ] 城市轮播是玩家端唯一允许横向滑动的区域；手机、桌面键盘与辅助交互均可浏览路线。
- [ ] 在常见手机宽度下，用户可以完整填写、校验、计算和查看结果，无横向滚动。
- [ ] 关卡选择、三星目标、当前收入、预算、成本偏好、食物候选和纪念品按既定顺序清晰呈现。
- [ ] 食物未勾选时不增加校验负担；勾选后输入与名称、分类紧邻。
- [ ] 已允许纪念品时必须填写库存；库存为 0 与留空在视觉提示和校验结果上可清晰区分。
- [ ] 校验在离开字段时反馈，提交时进行全量检查；隐藏错误区块会自动展开并定位。
- [ ] 成功结果一次只展示一个方案，且完整展示收入、食物、纪念品、成本、预算余量与偏好。
- [ ] 已达三星、无解、输入不足、计算中和计算失败都有明确文字化状态。
- [ ] 结果页返回后，用户的原输入仍可修改；清除草稿需二次确认且不再恢复已清除数据。

### 13.2 管理端

- [ ] 未通过共享口令时无法进入任何标准数据维护页。
- [ ] 登录后默认打开上海标准关卡，并可通过固定侧栏切换全部四个既定模块。
- [ ] 所有管理列表提供对应字段搜索、可读加载状态、初始空状态与搜索无结果状态。
- [ ] 单条新增 / 编辑使用右侧编辑面板；删除需要独立二次确认。
- [ ] 分类被引用时，删除入口能明确阻止并说明先迁移或删除关联项目。
- [ ] 食物目录达到 10 项时，新增与违规导入均有清晰阻止提示。
- [ ] 纪念品严格固定为两条可编辑配置，不显示新增、删除、导入或导出能力。
- [ ] 关卡与食物目录导入失败时，独立导入结果页列出全部错误行、字段和原因，并明确说明未写入任何数据。
- [ ] 宽屏优先保障表格与右侧编辑效率；窄屏导航、列表和编辑面板按本规范降级而不丢失关键信息。

## 14. 非目标

本规范不引入或暗示以下能力：玩家账户、跨设备同步、玩家历史、自动读取游戏数据、未开放城市的关卡、食物目录、纪念品配置或计算能力、设备升级与产能模拟、升级链、多个方案、方案比较、排行榜、攻略、支付、管理员账户体系、权限分级、口令修改、审计日志、纪念品批量导入导出、管理仪表盘。
