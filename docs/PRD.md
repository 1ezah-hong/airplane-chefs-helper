# Chefs Help Chefs MVP：产品需求文档

**Slogan：** Smarter plans. More stars.  
**状态：** 已确认；UI/UX 设计进行中，不进入实施计划  
**更新日期：** 2026-09-10  
**产品形态：** 移动优先的城市引入页与玩家计算器 + 桌面优先的受口令保护管理后台

## 1. 产品概述

Chefs Help Chefs 是《飞机大厨》的辅助决策工具，slogan 为“Smarter plans. More stars.”。它帮助玩家在指定城市和关卡距离三星目标仍有收入缺口时，基于本次可用的食物升级与纪念品，找到一个满足资源预算的单一最优方案。

首发目的不是建设完整攻略平台，而是验证下列闭环：管理员可独立维护可信标准数据；玩家可在手机上独立完成一次可信的三星方案计算。

## 2. MVP 范围

### 2.1 纳入范围

- 首发仅支持纽约机场的标准关卡，编号 1–50。
- 玩家匿名使用，无需账号和登录。
- 玩家端默认先进入城市引入页，再从纽约进入计算器；玩家可选择关卡、填写收入和资源预算、录入本次食物升级数据、按需允许使用纪念品，并得到一个最优方案。
- 城市引入页展示完整城市路线；纽约是唯一已开放且可进入的城市，其他城市仅显示“暂未开放”。
- 管理端使用一个部署时预设的共享管理员口令保护。
- 管理端维护关卡三星目标、食物分类、食物升级目录和两种纪念品配置。
- 玩家草稿自动保存在当前浏览器，并可由玩家手动清除。

### 2.2 明确不纳入范围

- 玩家账号、跨设备同步、云端玩家历史、收藏或社交功能。
- 自动读取游戏账户、游戏库存或关卡数据。
- 未开放城市的关卡、食物目录、纪念品配置或计算能力。
- 设备类升级、订单/制作时间模拟、产能模拟及其他间接收入机制。
- 多等级升级链、升级前置条件、升级互斥关系或一次计算中的重复升级。
- 备选方案、所有方案列表、方案比较、排行榜、攻略内容、支付与运营分析。
- 管理员账号体系、权限分级、改密、审计日志和纪念品批量导入导出。

## 3. 用户与成功标准

### 3.1 用户

- **玩家：** 从城市路线中进入纽约，并希望知道如何以现有或可购买资源达到某个纽约标准关卡的三星收入目标。
- **管理员：** 维护玩家端所依赖的关卡、食物目录与纪念品标准配置。

### 3.2 成功标准

- 玩家可在手机上无需他人协助完成一次可信计算。
- 管理员可无需开发人员协助维护并发布标准数据。
- 对任意合法输入，推荐方案可被独立复核：达到三星、符合预算，并符合所选成本偏好。

## 4. 角色与访问控制

| 角色 | 访问方式 | 能力 |
| --- | --- | --- |
| 匿名玩家 | 直接访问玩家端 | 进行计算、恢复或清除本机草稿 |
| 管理员 | 输入共享管理员口令 | 维护标准数据、导入、导出 |

共享口令由部署配置提供。后台内不提供口令修改、找回、管理员账号或权限管理。

## 5. 标准数据

### 5.1 城市路线展示配置

城市引入页按以下固定顺序展示城市：

丹佛 → 悉尼 → 伦敦 → 纽约 → 新加坡 → 东京 → 那不勒斯 → 里约热内卢 → 开普敦 → 巴黎 → 雅加达 → 洛杉矶 → 墨西哥 → 孟买 → 札幌 → 柏林 → 上海 → 布宜诺斯艾利斯。

纽约是唯一已开放城市；其余 17 座城市（包括上海）均为未开放状态。引入页首次加载时，必须将纽约定位于选择器中央并作为默认选中项。未开放城市可以被浏览和选中，但不得进入计算器；选中时在当前城市卡内显示“暂未开放”。

该路线仅是前端展示与未来扩展入口，不属于后台维护数据，不为未开放城市创建关卡、食物升级目录或纪念品配置。

### 5.2 纽约标准关卡

每条记录包含：

| 字段 | 规则 |
| --- | --- |
| 机场 | 固定为“纽约” |
| 关卡类型 | 固定为“标准关卡” |
| 关卡编号 | 1–50 的整数 |
| 三星目标收入 | 正整数 |

关卡唯一键为“机场 + 关卡类型 + 关卡编号”。现有资料中的 `points` 映射为三星目标收入，且与玩家填写的当前总收入使用同一单位。

### 5.3 食物分类与食物升级目录

管理员维护一份食物分类列表。每个食物升级项必须属于一个已有分类。

食物升级目录适用于纽约全部标准关卡，每个机场最多 20 项。目录每项仅包含：

| 字段 | 规则 |
| --- | --- |
| 名称 | 唯一、必填 |
| 分类 | 必填，必须引用已有食物分类 |

目录不保存食物等级、收入增量、金币成本或钻石成本。这些是玩家针对本次“当前状态 → 目标等级”的一次性升级输入。

分类被任一升级项引用时，管理员不可删除该分类；系统提示先迁移或删除关联升级项。食物目录达到 20 项后，新增与导入第 21 项均被拒绝。

纽约已确认标准数据包含 50 个标准关卡、4 个食物分类、12 项食物目录和 2 种纪念品配置。其唯一数据来源为 `AIRPALNE INFORMATION NEW YORK.xlsx`；不从旧上海数据推断或补充任何值。

- 食物分类：配菜、主食、甜品、饮料。
- 食物目录及固定顺序：泡菜、切片奶酪、蛤蜊杂烩、面包、烟熏肉、半月曲奇、芝士蛋糕、玻璃杯、奶油汽水、咖啡豆、咖啡杯、牛奶。
- 纪念品：slot 1 为自由帽（单个收入 60、每包 5 个、每包 1 钻石）；slot 2 为苹果徽章（单个收入 130、每包 5 个、每包 2 钻石）。

### 5.4 纪念品配置

MVP 固定两种纪念品。每种配置包含：

| 字段 | 规则 |
| --- | --- |
| 名称 | 必填 |
| 单个收入增量 | 正整数 |
| 每包数量 | 固定为 5，不可修改 |
| 每包钻石价格 | 非负整数；两种可分别配置，例如 1 与 2 |

管理员可逐条编辑纪念品名称、单个收入增量和包价。纪念品不支持 CSV/XLSX 导入导出。

## 6. 玩家端输入与校验

### 6.1 关卡与当前状态

1. 玩家首先在城市引入页进入已开放城市“纽约”。
2. 纽约计算器固定显示当前城市“纽约”。
3. 玩家从标准关卡 1–50 中选择一关；系统自动显示该关三星目标收入。
4. 玩家填写当前总收入。其含义是：**未使用纪念品、在当前配置下完成该关全部订单的总收入**。

当前总收入必填，为允许 0 的非负整数；不可为空、不可为小数或负数。

### 6.2 资源预算与偏好

玩家可分别填写金币预算和钻石预算。每项可留空，留空表示该资源不限；如填写，必须为允许 0 的非负整数。

玩家必须选择一个成本偏好：

- 优先省金币；或
- 优先省钻石。

### 6.3 食物升级输入

玩家端展示后台目录中的最多 20 项食物。每项有一个是否纳入计算的勾选框。

- 未勾选的食物不参与校验和计算。
- 勾选后，玩家必须填写本次升级的收入增量、金币成本、钻石成本。
- 收入增量为正整数；两类成本为允许 0 的非负整数；均不可为空、小数或负数。
- 每个目录项在一次计算中只能作为一个升级候选出现 0 或 1 次。

这表示一行输入是一次从当前状态升级到目标等级的汇总数据。MVP 不支持逐级、多次或连续升级。

### 6.4 纪念品输入

每种纪念品有独立的“允许使用”勾选框和库存输入框。

- 未勾选：该类纪念品不可参与本次计算，库存无需填写。
- 勾选：库存必填，为允许 0 的非负整数。
- 库存为 0：允许系统购买该纪念品，但没有免费库存可用。
- 库存字段为空不等同于 0；勾选后为空时，系统阻止计算并提示填写库存。

玩家不填写纪念品使用数量。系统只在被允许的纪念品类型中自动确定使用数量。

### 6.5 可计算前提

若当前总收入低于三星目标，且玩家未勾选任何食物升级、也未允许任何纪念品，系统阻止计算，提示玩家至少选择一项食物升级或允许一种纪念品。

## 7. 计算与最优方案规则

### 7.1 基础符号

- `T`：三星目标收入。
- `R`：当前总收入。
- `G = max(0, T - R)`：收入缺口。
- 每个已勾选食物升级 `j`：收入增量 `ΔRj`、金币成本 `Cj`、钻石成本 `Dj`，且选择变量 `xj ∈ {0, 1}`。
- 每种被允许纪念品 `i`：单个收入增量 `Mi`、库存 `Si`、包价 `Pi`、使用数量 `Qi ∈ 非负整数`。

### 7.2 达星条件

任何推荐方案必须满足：

`R + Σ(xj × ΔRj) + Σ(Qi × Mi) ≥ T`

### 7.3 纪念品库存与购买

纪念品优先使用库存，库存不足时按整包购买：

`购买包数 Bi = max(0, ceil((Qi - Si) / 5))`

`购买数量 = 5 × Bi`

`纪念品钻石成本 = Bi × Pi`

结果中的库存消耗数量为 `min(Qi, Si)`；购买后的剩余数量为：

`Si + 5 × Bi - Qi`

该剩余数量仅用于指导玩家本次实际操作；系统不自动将其写回游戏库存或建立长期库存账户。

### 7.4 预算约束

`食物金币总成本 = Σ(xj × Cj)`

`钻石总成本 = Σ(xj × Dj) + Σ(Bi × Pi)`

如填写金币预算，食物金币总成本不得超过它；如填写钻石预算，钻石总成本不得超过它。两项预算均可独立留空。

### 7.5 最优方案排序

从所有满足达星条件与预算约束的方案中，选择唯一展示的第一名：

1. 先最小化玩家选定的优先资源成本（金币或钻石）。
2. 再最小化另一种资源成本。
3. 再最小化已选择的食物升级项数量。
4. 再最小化纪念品使用总数量。
5. 若仍完全相同，按稳定、确定的目录顺序打破平局，确保同一输入始终返回同一方案。

### 7.6 无解与无上限边界

- `R ≥ T` 时，不计算方案，直接提示“当前配置已满足三星，无需升级”。
- 若任一允许纪念品的单个收入增量为正，且钻石预算不限，则总能通过购买足够纪念品达星，不会出现无可行方案。
- 只有在收入存在缺口，且食物与允许纪念品在资源预算下均不足以补齐缺口时，才显示“暂未找到可行升级方案”。
- 无解状态显示收入缺口及有限的最大可增加收入。由于钻石不限时纪念品可无限购买，此状态不会在该条件下出现，也不会显示“无上限”作为无解结果。

## 8. 用户流程与结果页面

### 8.1 玩家主流程

1. 打开城市引入页，默认定位纽约。
2. 点击纽约并进入纽约计算器。
3. 选择纽约标准关卡。
4. 填写当前总收入、可选预算和成本偏好。
5. 录入零到二十项食物升级候选。
6. 按需允许纪念品并填写库存。
7. 点击“计算最佳方案”。
8. 查看唯一最优方案、已达三星状态，或无可行方案状态。

### 8.2 成功结果

结果页至少展示：

- 所选关卡、三星目标、当前收入、收入缺口。
- 推荐食物升级清单：名称、分类、收入增量、金币成本、钻石成本。
- 推荐纪念品清单：使用数量、原库存消耗、购买包数、购买数量、购买后剩余数量和钻石成本。
- 预计新增收入、方案后总收入、超过三星目标的收入余量。
- 金币总成本、钻石总成本，以及相对已填写预算的剩余额度。
- 玩家选择的成本偏好。

只展示一个最优方案，不展示备选方案、全部组合或手动比较功能。

### 8.3 非成功状态

| 情况 | 行为 |
| --- | --- |
| 当前收入已达三星 | 提示“当前配置已满足三星，无需升级” |
| 有收入缺口但未选择食物且未允许纪念品 | 阻止计算并提示至少选择食物升级或允许纪念品 |
| 字段非法或纪念品已允许但库存缺失 | 在字段旁显示明确校验信息并阻止计算 |
| 预算内无解 | 提示“暂未找到可行升级方案”，显示收入缺口及有限最大可增加收入 |

## 9. 本地草稿

玩家端自动在浏览器本地保存最近草稿，包括关卡、当前收入、预算、成本偏好、食物勾选与数值、纪念品允许状态与库存。

刷新或重新打开页面时恢复草稿。玩家可执行“清除草稿”；清除后，下次加载不恢复此前输入。草稿不上传为玩家档案，也不跨设备同步。

## 10. 管理端操作与数据导入导出

### 10.1 单条维护

纽约标准关卡、食物分类、食物升级目录、纪念品配置均提供列表、搜索、新增、编辑和删除。所有删除操作需要二次确认。

### 10.2 批量导入导出

纽约标准关卡与食物升级目录各自独立导入、导出，且均支持 CSV 和 XLSX：

| 数据集 | 导入/导出 | 唯一键 | 关键规则 |
| --- | --- | --- | --- |
| 纽约标准关卡 | 独立 CSV/XLSX 文件 | 机场 + 关卡类型 + 关卡编号 | 机场必须为纽约、类型必须为标准关卡、编号 1–50、目标收入为正整数 |
| 食物升级目录 | 独立 CSV/XLSX 文件 | 名称 | 分类必须已存在；全量记录后目录不得超过 20 项 |

导入采用原子方式：系统先校验文件内所有行和与现有数据的冲突；只要存在错误，整份文件不写入。界面须返回全部错误行与可理解的错误原因。

成功导入后，按唯一键新增或更新；导入文件未包含的既有记录必须保留。食物分类和纪念品不在批量文件范围内。

## 11. 界面与体验要求

- 玩家端移动优先：城市路线浏览、核心填写、校验、计算和结果在常见手机宽度下可完整操作；城市选择器允许其自身横向滑动，其他页面内容无需横向滚动。
- 管理端桌面优先：数据表格、搜索、编辑和导入错误清单以效率与可读性为优先。
- 视觉语言使用清晰的航空主题与蓝色系业务界面；视觉装饰不得妨碍表单、预算、成本和结果数值的阅读。
- 重要金额、目标、缺口、预算剩余与错误提示必须有清晰标签，不能仅依赖颜色传达。

## 12. 验收清单

### 12.1 玩家端

- [ ] 玩家首次进入先看到城市引入页，纽约默认选中并居中显示。
- [ ] 可横向浏览 18 座城市；纽约可进入计算器，其余 17 座城市仅在卡片内显示“暂未开放”，不可进入计算器。
- [ ] 可选择纽约 1–50 任一标准关卡，且三星目标与后台数据一致。
- [ ] 可正确校验所有必填、整数、正负和纪念品库存规则。
- [ ] 可选择任意零到二十项食物升级；每项不重复参与计算。
- [ ] 在预算存在或留空时，计算均正确执行对应约束。
- [ ] 已达三星、输入不足、预算无解和有解四类状态均按本规格呈现。
- [ ] 推荐方案达到三星、未超预算，并符合玩家选定的成本偏好及平局规则。
- [ ] 纪念品库存优先、整包购买、钻石成本、购买余量的计算均正确。
- [ ] 草稿自动恢复，且清除草稿后不再恢复。

### 12.2 管理端

- [ ] 未通过共享口令不得访问管理数据或写入接口。
- [ ] 管理员可独立维护关卡、分类、食物目录和两种纪念品配置。
- [ ] 分类被引用或目录超过二十项时，系统正确阻止破坏性操作。
- [ ] 两种 CSV/XLSX 数据集均可独立导入导出。
- [ ] 导入可完整报告错误且不产生部分写入；合法文件按唯一键正确新增或更新。
- [ ] 管理端成功保存的数据可供玩家端下一次计算使用。

## 13. 后续版本候选

- 更多机场、关卡类型和每关差异化的升级目录。
- 食物升级等级树、前置条件、升级链和设备类间接收入模拟。
- 更完整的纪念品类型、库存同步与复杂效果。
- 玩家账号、跨设备草稿/收藏和计算历史。
- 多方案展示、方案对比、按玩家偏好自定义排序。
